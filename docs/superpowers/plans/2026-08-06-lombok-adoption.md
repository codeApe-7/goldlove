# Lombok Adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce Java backend boilerplate with Lombok without changing public behavior or exposing sensitive entity fields through generated string methods.

**Architecture:** Lombok remains a compile-time-only dependency. Persistence entities use getters/setters while sensitive array accessors stay explicit; configuration classes and assignment-only Spring constructors use narrow annotations.

**Tech Stack:** Java 25, Spring Boot 4.1, Lombok, MyBatis-Plus, JUnit 6, Testcontainers

## Global Constraints

- Do not use `@Data`, class-level `@ToString`, or `@Value` on persistence entities.
- Keep defensive copies in all sensitive `byte[]` accessors.
- Keep Java records for API DTOs and preserve every existing method signature.
- Do not add Mapper XML; simple persistence continues to use MyBatis-Plus built-ins and lambda wrappers.
