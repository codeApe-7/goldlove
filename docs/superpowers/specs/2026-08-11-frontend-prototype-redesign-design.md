# 婚恋智能档案库前端高保真重构设计

## 背景与目标

当前项目已经完成嘉宾端建档闭环和管理后台审核闭环，但前端仍采用早期暖玫瑰卡片风格，与最新原型图不一致。本次同时重构 `apps/guest-app` 与 `apps/admin-web`，以用户提供的两张原型图为高保真标准，在不改变后端接口、业务规则和主要操作路径的前提下，统一为黑、白、暖灰的高保真婚恋档案视觉体系。

本次验收重点是页面结构、信息密度、颜色、字体层级、边框、圆角、间距、状态表达和主要交互与原型一致。嘉宾端以 390px 左右的移动视口为主，管理后台以 1440px 桌面视口为主，并保证常见相邻尺寸仍可使用。

## 已确认决策

- 同时改造嘉宾端 5 个页面与管理后台 6 个页面。
- 原型图是视觉和布局的高保真验收标准。
- 保留 Vue、uni-app、Pinia、Vue Router、Element Plus、现有 API 封装及业务逻辑。
- 采用结构级重构：调整页面模板和样式，抽取少量复用展示组件，不重写数据层。
- 不新增后端接口，不实现原型中超出现有后端能力的新数据。
- 上传照片、表单字段、统计数字、状态和审核差异全部继续显示真实接口数据。

## 视觉方向

### 设计语言

界面表达“私密、克制、可信、专业”。视觉主体使用无彩色体系，品牌温度通过小面积香槟金标识和细腻材质感体现，而不再使用大面积玫瑰色。装饰严格收敛，重点依靠精确的留白、细边框、字重和明暗对比建立品质感。

登录页的竖线品牌标识与暗色等高线纹理是唯一签名元素。其余页面保持安静，避免无业务含义的渐变、光晕和装饰性图表。

### 色彩令牌

| 角色 | 颜色 | 用途 |
| --- | --- | --- |
| 墨黑 | `#0D0D0F` | 主按钮、深色侧栏、品牌卡、主要文字 |
| 石墨 | `#1E1E22` | 深色表面次级层、悬停状态 |
| 辅助灰 | `#6B6C70` | 次要信息、说明、占位文本 |
| 边框灰 | `#E5E3DF` | 分割线、输入边框、卡片边界 |
| 暖白 | `#F7F6F3` | 页面背景 |
| 纯白 | `#FFFFFF` | 卡片、表格、表单表面 |
| 香槟金 | `#C9A96A` | 品牌标识与极少量强调 |
| 成功绿 | `#22C55E` | 已通过、成功反馈 |
| 警告黄 | `#F59E0B` | 待审核、临期提示 |
| 错误红 | `#EF4444` | 退回、错误与危险操作 |

### 字体与尺寸

- 中文主体：`PingFang SC`、`Microsoft YaHei`、系统无衬线字体回退。
- 数字与编号：系统等宽数字特性 `font-variant-numeric: tabular-nums`。
- 移动端主标题 20–24px、分区标题 14–16px、正文 14px、辅助信息 12px。
- 管理端页面标题 22–24px、卡片数字 28–32px、正文与表格 13–14px、辅助信息 12px。
- 主要按钮使用 600 字重，普通正文保持 400，避免全局粗体。

### 圆角与间距

- 使用 4px 基础间距系统；常用间距为 8、12、16、24、32px。
- 移动端卡片圆角 12px，输入与按钮 6–8px，深色品牌卡 14px。
- 管理端卡片和面板圆角 8px，输入与按钮 4–6px，表格边界保持克制。
- 阴影只用于浮层、移动端品牌卡和登录容器，常规卡片以细边框区分。

## 嘉宾端设计

### 全局结构

- H5 内容在宽屏浏览器中居中显示，最大宽度约 430px；在真实移动设备中占满视口。
- 使用暖白背景、白色内容分区和固定底部三栏导航。
- 页面需要为底部导航和安全区预留空间。
- 导航栏与页面标题采用黑色文字，不使用旧暖玫瑰主题色。
- 底部 Tab 使用线性图标、短标签和黑色选中状态；不增加现有路由之外的入口。

### 登录与激活 `/pages/auth/index`

- 上半区为约 250px 高的墨黑品牌区，包含香槟金竖线标识、产品名、副文案和极低对比度等高线纹理。
- 下半区为白色表单面板，上缘覆盖品牌区并形成轻微浮层关系。
- 登录与激活使用双标签切换；激活模式显示手机号、初始凭证和新密码，登录模式显示手机号和密码。
- 输入框为浅灰细边框，主按钮为整行墨黑实心按钮。
- 底部显示隐私保护说明与客服电话；现有项目没有动态客服接口，因此电话号码使用原型中的静态展示文案，不参与业务请求。
- 保持现有登录、激活、加载、错误提示和成功跳转逻辑。

### 授权书 `/pages/consent/index`

- 顶部为紧凑导航标题与返回入口。
- 正文区域使用纯白纸张式排版，显示标题、版本号、更新日期及接口返回的授权书正文。
- 若接口未单独提供结构化章节，正文按原始换行展示，不擅自改变法律文本内容。
- 同意勾选和“同意并继续”按钮固定在页面底部操作区，正文滚动不影响操作入口。
- 未勾选时按钮保持禁用视觉并显示现有提示。

### 档案 `/pages/profile/index`

- 顶部显示“我的档案”、完成度和细进度条。完成度由启用字段的已填写数、必填头像和可用照片区综合计算，仅作为前端展示，不改变提交校验。
- 动态字段根据现有字段定义按语义分为“基本资料”“职业与收入”“社交账号”；未知动态字段归入“更多资料”。分组只影响显示，不改变请求载荷。
- 每个分区为白色列表卡，行内显示标签、当前值和右侧箭头；文本与数字字段点击或聚焦后仍使用现有输入能力，选择、日期和布尔字段保持对应控件。
- 个人影像分区保留头像 1 张、生活照最多 6 张、上传覆盖和删除规则；图片按原型使用方形缩略图网格。
- 底部操作区提供“保存草稿”和“提交审核”，在移动端保持可见并尊重安全区。
- 所有必填、类型、头像、乐观锁和幂等提交校验保持现状。

### 状态 `/pages/status/index`

- 顶部深色总览卡展示当前状态、提交时间、预计完成时间和三段式进度轨迹。
- 现有状态接口未提供提交时间和截止时间时，对应字段不伪造数据，改为显示状态说明或隐藏时间行。
- 下方按业务状态显示一个主状态卡：待审核、已通过、被退回或未提交。使用绿、红、灰小面积状态图标与标签。
- 被退回时保留“去修改”操作；未提交时提供“去完善档案”；已通过时可显示已通过版本入口，但只在现有 revision ID 可用时开放。
- 退回具体原因若现有接口不可得，仅保留通用说明，不模拟后端不存在的数据。

### 我的 `/pages/mine/index`

- 顶部深色身份卡展示匿名账户信息。现有会话没有昵称和头像字段，因此默认显示档案品牌头像和脱敏账号 ID，不伪造真实昵称或手机号。
- 授权状态和有效期单独成卡，继续显示真实授权版本和到期时间。
- 将授权书、隐私政策、用户协议、账户与安全、帮助与反馈、联系客服组织为设置列表。其中只有现有“查看/重新同意授权书”和“退出登录”具备业务跳转；其余原型入口以明确的“暂未开放”反馈处理，不创建无功能页面。
- 退出登录采用红色文本按钮并保持现有会话清理逻辑。

## 管理后台设计

### 全局框架

- 登录后采用固定深色侧栏、白色顶栏与暖白内容区。
- 侧栏宽约 164px，品牌标识置顶，四个现有菜单使用白色线性图标；选中项使用较浅的石墨背景和左侧细高亮条。
- 顶栏约 52px，高度紧凑，右侧显示无未读标记的通知图标、管理员头像/名称和退出入口。通知图标只作原型视觉还原，不连接新接口，点击时提示通知功能暂未开放。
- 内容区设置最大可读宽度并保留 24px 左右内边距；小于 1100px 时允许关键表格横向滚动，表单列改为单列或缩短侧栏。

### 登录 `/login`

- 页面左侧为深色品牌栏，右侧居中放置白色登录面板，整体接近原型中的浏览器画布比例。
- 面板包含香槟金品牌标识、产品名、管理后台副标题、账号、密码、记住我视觉选项、找回密码提示和墨黑登录按钮。
- “记住我”和“忘记密码”没有后端能力时不产生虚假流程：记住我不改变 HttpOnly Cookie 策略，忘记密码提示联系系统管理员。
- 保留现有登录校验、加载和错误反馈。

### 工作台 `/dashboard`

- 页面标题下显示一行简短说明。
- 四项统计以等宽卡片展示真实数字。当前接口无同比数据，因此不展示虚假的较昨日增量，只保留静态口径说明。
- 增加“最近待处理审核”表格和“SLA 提醒”环形图仅在现有接口可支持时实现。现阶段无对应聚合接口，因此页面保持四项统计主内容，并以待审核数生成简单提醒文案，不额外请求或伪造列表。
- 卡片与原型一致采用白底、细边框、左对齐数字。

### 访客登记 `/guests/register`

- 页面采用左侧主表单、右侧凭证结果与补发面板的两栏布局。
- 主表单字段和提交数据完全沿用现有实现；必填星号、帮助文本和金额单位更清晰。
- 成功后在右栏突出显示一次性初始凭证，提供复制能力；页面刷新后不持久化凭证。
- 补发凭证单独使用手机号输入，避免与登记表单共享可变手机号导致误操作；提交前保留明确的作废旧凭证说明。

### 字段配置 `/field-definitions`

- 采用原型的紧凑表格、顶部说明、新增字段按钮和底部分页。
- 类型、存储、必填和启用状态转换为中文标签或开关视觉；不新增后端未支持的删除操作。
- 新增/编辑继续使用对话框，核心字段不可修改项保持禁用并提供原因说明。
- 表格在窄屏允许水平滚动，不挤压字段代码和操作列。

### 审核管理 `/reviews`

- 顶部显示状态分段统计标签。由于现有列表 API 不提供全量分状态聚合，标签用于切换筛选，数量只在当前接口可确定时显示。
- 筛选区包含状态、截止时间和档案编号，查询按钮使用墨黑主样式，重置按钮为次级样式。
- 表格状态全部转换为中文标签；行悬停可点击，操作列提供“查看”。
- 分页、加载态和空结果提示保持可用。

### 审核详情 `/reviews/:id`

- 顶部独立标题栏包含返回入口、档案编号和版本 ID。
- 内容区采用“档案信息 + 版本差异 + 审核操作”的主栏，以及“审核操作/审核须知”的窄侧栏。
- 档案字段使用两列信息网格；照片使用横向缩略图墙并保留放大预览。
- 差异表以灰色旧值、箭头和绿色新值呈现；无差异时显示明确空状态。
- 待审核时侧栏固定显示“通过”“退回”和退回说明输入；后端仍要求退回说明非空。已完成审核时显示结果，不允许重复修改。
- 通过确认、退回校验、乐观版本和错误处理全部复用现有 API 逻辑。

## 组件与代码边界

### 嘉宾端

- `src/styles/`：新增全局设计令牌和通用页面规则。
- `src/components/BrandMark.vue`：竖线品牌标识。
- `src/components/AppIcon.vue`：无外部图标依赖的轻量 SVG 图标封装，兼容 H5 与后续小程序构建约束。
- `src/components/SectionCard.vue`：移动端分区卡。
- `src/components/StatusBadge.vue`：业务状态中文映射与颜色。
- 页面保留现有 store 和 API 调用，模板层只消费响应式状态。

### 管理后台

- `src/styles/theme.css`：重建 CSS 令牌、Element Plus 覆盖和通用布局。
- `src/components/BrandMark.vue`：管理端品牌标识。
- `src/components/PageHeader.vue`：统一页面标题和说明。
- `src/components/StatusTag.vue`：审核状态中文映射。
- `src/layouts/AdminLayout.vue`：只负责导航、顶栏、响应式外壳和退出。
- 业务页面继续通过现有 `api/admin.ts` 获取和提交数据。

组件只抽取在两个以上页面重复、且职责清晰的展示模式，避免为了抽象而拆分所有 DOM。

## 数据流与兼容性

1. 页面进入后继续由现有 store 或 API 方法加载真实数据。
2. 加载中显示骨架、局部 loading 或禁用按钮；不能因布局重构触发重复请求。
3. 页面将后端枚举转换为中文展示，但提交值仍使用原枚举。
4. 接口失败继续使用现有统一错误信息；页面级失败提供重试入口或明确提示。
5. 路由守卫、Cookie 会话、Origin 校验、幂等键与乐观锁行为不变。
6. 所有原型中而后端未提供的数据均隐藏、降级为静态说明或“暂未开放”，不得伪造业务记录。

## 响应式与无障碍

- 嘉宾端覆盖 320–430px 主流手机宽度，并在桌面 H5 中居中展示。
- 管理后台优先覆盖 1280–1600px；小于 1100px 时缩短侧栏、表单改列和表格滚动。
- 可点击元素保留明确 hover、active、disabled 和 `focus-visible` 状态。
- 图标按钮带可读标签或 `aria-label`；状态不只依赖颜色表达。
- 尊重 `prefers-reduced-motion`，只使用短促的颜色与位移过渡，不实现持续动画。
- 文本与背景达到可读对比度，触控目标尽量不小于 40px。

## 测试与验收

### 自动验证

- 管理后台：运行 `npm run test` 和 `npm run build`。
- 嘉宾端：运行现有 Vitest 命令、`npm run type-check` 和 `npm run build:h5`。
- 现有 API、store、路由守卫和校验测试必须继续通过。
- 对新增状态映射、完成度或纯函数逻辑补充单元测试；不为纯 CSS 复制脆弱快照测试。

### 视觉验证

- 嘉宾端以 390×844 左右视口逐页截图：登录/激活、授权书、档案、四种状态、我的。
- 管理端以 1440×900 左右视口逐页截图：登录、工作台、访客登记、字段配置、审核列表、审核详情。
- 将截图与原型并排检查：外壳比例、主分区、字体层级、对齐、间距、圆角、边框、颜色、按钮层级和状态表达。
- 额外检查 320px 嘉宾端、1280px 管理端，确保无不可操作的遮挡或横向页面溢出。

## 不在本次范围

- 新增或修改后端 API、数据库和业务状态机。
- 微信登录、线上支付、通知、直播、素材管理和密码找回。
- 为原型中的示例昵称、手机号、审核时间、增长比例或记录构造假数据。
- 将嘉宾端改为原生 App，或单独实现微信小程序专属界面。
- 暗色模式、国际化和新的第三方 UI/图表依赖。

## 完成标准

- 两端所有现有页面均完成原型风格的结构级重构。
- 关键页面在目标视口下与原型的视觉层级和布局高度一致，不再保留旧暖玫瑰主题痕迹。
- 原有核心流程可继续完成，现有自动测试、类型检查和生产构建通过。
- 不展示无法由现有接口支撑的虚假业务信息。
- 完成逐页视觉截图复核，并修正明显的溢出、错位和交互不可达问题。
